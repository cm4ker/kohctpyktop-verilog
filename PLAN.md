# План объединения КОНСТРУКТОРА и Verilog-синтезатора

Статус: выполняется. Исходные проекты и solutions.v сохраняются без изменений; рабочая сборка готовится в kohctpyktop-app, Git создаётся только вне песочницы.

1. Подготовить единый проект: игровой движок, ресурсы, синтезатор, библиотека, тесты, примеры и solutions.v. Исключить node_modules, dist, кэши, логи, скриншоты тестов, ZIP, SWF, инструменты декомпиляции, исходные выгрузки Flash и локальные секреты. Сохранить атрибуцию Zachtronics.
2. Интегрировать синтезатор в игру: открытие из уровня, шаблон root с DIP-пинами, именами сигналов и комментариями, перенос схемы в активный уровень с отменой. Новую интеграцию писать на TypeScript; стабильный игровой движок пока оставить на JS, не маскировать типизацию через ts-nocheck.
3. Сделать заметную ссылку на оригинальную игру в верхней панели.
4. Добавить пользовательскую библиотеку localStorage: создание, редактирование, удаление, включение модулей. Системные модули доступны серым списком, по умолчанию выключены; включение явное. Экспорт/импорт библиотеки.
5. Перенести delay_line, por, rs_trigger в Verilog-библиотеку, описав через транзисторы. Добавить необходимую параметризацию и разворачивание повторений; сохранять особую физическую компоновку там, где это улучшает разводку.
6. Реализовать оптимизации: a & ~b одним P; объединение выходных сетей в OR только при отсутствии других потребителей; XOR по схеме из solutions.v. Зафиксировать реальные тактовые задержки.
7. Разрешить перестановку безопасных последовательных транзисторов при разводке; не переставлять каскады задержки и устройства с отводами промежуточных узлов.
8. Разобрать solutions.v в отдельные проверяемые варианты, привязать к уровням; не скрывать альтернативные или неполные варианты. Автоматически синтезировать, разводить, запускать игровой симулятор, проверять порог прохождения.
9. Прогнать модульные и интеграционные тесты, браузерные сценарии, сборку и работу под префиксом GitHub Pages.
10. Создать внешний Git-репозиторий, проверить состав и секреты, сделать коммит. Создать публичный GitHub-репозиторий, настроить Actions → Pages, push и проверить опубликованную страницу. Owner/путь уточняются; публикация уже разрешена пользователем.

## Проверка готовности

- Все новые функции доступны из одного приложения; данные сохраняются после перезагрузки.
- Решения действительно проверяются движком игры, а не только логическими таблицами.
- Репозиторий воспроизводимо устанавливается через npm ci и собирается без локальных путей.
- Никакие токены и личные сохранения не попадают в Git.
- Публикация считается выполненной только после успешного развёртывания, иначе фиксируется точная причина блокировки.
